# 精神离职 · Mind Offline

> 人可以不清醒，饭不能不吃。

一个打工人精神状态主题的虚拟点餐实验。没有真实食品、支付、充值或配送。

- 顾客试玩：<https://mind-offline.duckdns.org/>
- 店长后台：<https://mind-offline.duckdns.org/admin/>

## 技术与目录

| 目录 | 技术 | 用途 |
| --- | --- | --- |
| `miniapp/` | uni-app + Vue 3 + TypeScript | 同一份顾客端代码构建网页和微信小程序 |
| `admin/` | Vue 3 + Vite + TypeScript | 手机/电脑均可使用的店长后台 |
| `server/` | Go 标准库 HTTP + pgx | API、事务、身份校验、静态资源托管 |
| `deploy/` | Docker Compose + Caddy | 运行配置、HTTPS 入口示例 |
| `scripts/` | Python 标准库 | 构建、部署、API 冒烟检查 |

Go 程序嵌入两套编译后的网页。服务器只增加一个应用容器；PostgreSQL、Caddy 复用现有实例。PostgreSQL 中使用独立的 `mind_offline` 数据库和角色。应用监听 `127.0.0.1:18082`，经 Caddy 对外提供 HTTPS。

## 第一版功能

- 29 款初始抽象菜品、分类、菜名/描述/分类实时搜索、售罄显示、精神状态规格、购物袋和备注。搜索可与分类叠加，支持空格分隔多个关键词和一键重置。
- 2026-10-10 扩充的20款菜单通过一次性迁移添加，使用自动编号，不覆盖已有菜单；重启不会重复添加，也不会复原店长之后的编辑。
- 用户名/密码注册登录，新账号获得 300 精神值，每天（北京时间）可领取 100。
- 账号隔离订单、精神值与本地购物袋，支持多设备登录；退出会撤销当前会话。
- 服务器核算价格，事务扣款，幂等下单；失败不扣款，取消只退款一次。
- 顾客仅能查看自己的订单，页面显示时每 8 秒更新菜单、余额和订单。
- 订单自动流程：下单 → 30 秒制作中 → 60 秒可取餐 → 90 秒已完成；前两步仍可由店长取消退款，无需人工推进。
- 随机抽象评语和可保存的 PNG 小票。
- cole 唯一管理员，后台包括经营概览、订单管理、顾客档案、菜单管理和 AI 会话记录。
- 经营概览：今日订单/精神值流水、注册人数、待处理队列、近7天趋势、热门菜品和最近注册顾客。
- 订单管理：按用户名/订单号搜索、状态筛选、每页20笔分页；订单直接关联顾客详情。
- 顾客档案：用户名/ID搜索、正常/停用筛选、注册/最近登录时间、余额、订单统计、常点菜品、全部历史订单分页和店长备注。
- 停用顾客会撤销其全部会话并禁止登录；恢复后必须重新登录。保留原有余额和订单，不自动取消未完成订单。
- 菜单新增/编辑/售罄、名称与文案搜索、供应状态筛选。

顾客用户名为 3—24 位字母、数字或下划线，不区分大小写；密码至少 8 个字符、最多 72 字节，使用 bcrypt 加盐哈希存储。顾客会话有效期 30 天，服务端只存会话令牌哈希；登录失败按 IP 和用户名限流。所有私有接口从会话推导账号，不接受前端指定订单归属。不同账号无法互相查看、扣减或修改订单。店长仍可查看所有顾客订单，出餐由系统自动推进。顾客管理接口仅允许店长访问，使用明确字段清单返回资料，不返回密码哈希或登录凭证。手机号和地址尚未收集；最近登录从顾客管理版上线后开始记录，不补造历史时间。

旧访客数据不删除。注册时可明确勾选将本浏览器的历史数据绑定到新账号；服务端验证旧凭证、事务绑定并销毁旧凭证，不能重复转移。未勾选则创建独立的新账号；现有账号登录不自动合并历史数据。暂不提供自助找回密码。

后台会话有效期 12 小时，保存在标签页会话存储，可主动退出。全站纯模拟，精神值没有现金价值。

## 本地开发

环境：Go 1.26+、Node.js 22.12+ 或 24、npm、可连接的 PostgreSQL。前端依赖锁定在各自的 `package-lock.json`。

```sh
npm --prefix miniapp ci
npm --prefix admin ci
cd server
go mod download
```

参考 `server/.env.example` 设置 `DATABASE_URL`、`ADMIN_ACCOUNT_ID`（现有 cole 账号的固定 ID，留空关闭管理权限），再运行：

```sh
cd server
go run .
```

Go 启动时创建缺失的表、写入初始菜品；已有菜品不会被覆盖。开发时另开终端：

```sh
npm --prefix miniapp run dev:h5
npm --prefix admin run dev
```

两套 Vite 开发服务均将 `/api` 代理到本地 `127.0.0.1:18082`。顾客网页地址以命令输出为准；管理网页使用 `/admin/` 路径。首次从源码启动 Go 时尚无静态网页，使用 Vite 或先执行完整构建。

## 服务器部署

初始环境约定：已有 Caddy 容器 `jinx-https`、PostgreSQL 容器 `jinx-postgres`，均采用 host 网络。复用实例但不修改已有业务数据库。

一次性准备：由管理员创建专用数据库/角色，把运行环境写入服务器 `/opt/mind-offline/production.env`，权限设为 `600`。内容参考 `server/.env.example`，建议再设 `GOMEMLIMIT=140MiB`、`GOMAXPROCS=2`。

构建后运行：

```sh
python3 scripts/deploy.py
```

脚本通过已有 SSH 认证部署，使用带时间戳的镜像标签，健康检查失败会尝试恢复上一镜像。不保存 SSH 密码。需事先准备环境文件与 Caddy 域名入口（`deploy/Caddyfile.snippet`）。首次配置 Caddy 时备份原文件、验证配置后热加载，不重启现有服务。

容器限制：192 MiB 内存、0.75 CPU、最多 64 进程；非 root、只读文件系统、移除 Linux capabilities；日志按 5 MiB × 3 轮转。数据库连接池最多 5 个连接。限制仅针对 Go 容器，不涵盖已有 PG/Caddy；不代表承诺并发容量。

cole 使用食堂账号登录后进入管理后台，不再使用独立店长口令。不要把 `.secrets/` 或服务器的环境文件提交到仓库。

## 网易云音乐实验接入

顾客端的“音乐实验室”支持：扫码绑定、显示网易云昵称/头像、分页读取创建/收藏的歌单、跳转网易云以及解除绑定。现在支持食堂内播放：点开歌单，点击歌曲后出现底部播放器；支持暂停/继续、上一首/下一首、进度调整和自动播放已加载队列。切回点餐页继续播放，退出/换号/解绑停止。只使用网易云为当前账号返回的标准音质音源，不提供任何解锁或替代音源功能。微信端仅完成构建，未进行真机验证；请先使用网页体验。

这是基于第三方库的扫码登录方案，不是已经取得的网易云官方 OAuth 授权。首次扫码前页面要求用户明确同意本站保存登录凭证。真实扫码确认必须由用户在网易云 App 中完成；二维码可生成不代表一定能通过平台风控或读取全部歌单。

### 结构与凭证隔离

- `music-bridge/` 是独立的 Node.js 只读适配器，锁定 `@neteasecloudmusicapienhanced/api@4.41.1`，只导入二维码、账号信息、歌单详情和歌曲详情模块，通过标准音质接口取得播放地址，不启动其通用 API 服务。
- 适配器只监听服务器 `127.0.0.1:18085`，内部请求另需随机服务凭证。公网只能通过 Go 的顾客身份校验接口访问。
- Go 将网易云 Cookie 使用 AES-256-GCM 加密后存入 PostgreSQL。密文绑定食堂账号与用途；加密密钥存在服务器环境文件中，不存数据库或 Git。
- 二维码尝试绑定食堂账号和当前登录会话，有效期最多3分钟。退出、停用、取消和解绑都会使对应尝试失效；解绑与确认采用事务避免延迟响应重新绑定。
- 一个网易云账号同时只能关联一个食堂账号。歌单 UID 由绑定凭证推导，不接受顾客指定别人的 UID。
- 所有音乐 API 响应均禁止缓存。前端及店长后台不接收 Cookie、服务凭证或加密密钥。上游 SDK 原始日志被抑制，防止失败响应把 Cookie 打入日志。
- 解除绑定删除本站的凭证与未完成的二维码，不修改网易云歌单，也不替代网易云 App 的设备管理功能。
- 失效音乐凭证会删除密文并提示重新扫码，不注销食堂账号。接口风控或故障只影响音乐模块。

### 播放行为

- 歌曲列表每页30首，点击“加载更多歌曲”扩展当前播放队列；不在后台一次性拉取完整大歌单。
- 歌曲播放权以实时音源响应为准；仅试听时标注“试听”并限制进度范围，不可播放时提供网易云入口。
- 音频由顾客设备直接从经过校验的网易云 HTTPS CDN 读取，不经过本服务器转发，不缓存音乐文件。
- 播放地址只保留在当前页面内存，不写入本地存储；后端返回前重新验证当前绑定与登录会话。
- 浏览器若拦截异步播放，播放器提示再点击播放；不会自动切换到未授权音源。
- 跨页指食堂单页面内的菜单/订单等区域切换；不承诺关闭页面或手机锁屏后持续播放。

播放器状态测试位于 `miniapp/tests/player.test.mjs`，覆盖快速切歌、暂停加载、账号切换、关闭后的迟到响应、试听范围、浏览器播放拦截、队列切歌与恢复。`TestMusicIntegration` 另覆盖播放接口的账号鉴权、HTTPS 音源域名校验及解绑时不返回迟到音源。

## 酷狗音乐实验接入

音乐实验室现在提供“网易云音乐 / 酷狗音乐”切换。两个平台独立扫码绑定、读取歌单和播放已获准的音源；切换平台时停止当前播放，避免播放队列混用。点餐/订单页面之间切换仍可继续播放当前平台的音乐。

酷狗通过 [MakcRe/KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi) 的固定提交 `ba3645f2c89e6b9d4fec82ff783c15287e4c5f43` 接入，依赖 URL 与完整性摘要写入 npm lockfile。这不是酷狗官方 OAuth 授权；使用酷狗音乐 App 自行扫码确认，无需在食堂输入酷狗密码。

- 酷狗使用 `kugou_music_bindings` 和 `kugou_music_link_attempts` 独立存储；原网易云表及密文保持兼容。
- AES-GCM 的关联数据包含平台标识，网易云凭证不能被当成酷狗凭证解密。
- 每个平台独立处理二维码、账号凭证、曲目编号及 CDN 白名单。账号/会话校验、取消/解绑和延迟响应保护沿用原有机制。
- 歌曲使用标准音质，只播放平台返回且能确认的音源；遇到权限不足、验证要求、加密/未知试听格式时提示不可播放，不尝试绕过验证或解锁付费内容。
- 酷狗全曲/歌单数据需要真实账号扫码后验证；首次接入已验证真实二维码生成和“等待扫码”状态。网易云既有账号无需重新绑定。
- 2026-10-10 的集成测试使用独立测试数据库，分别运行两平台的账号隔离、会话绑定、播放和解绑并发测试，并检查解绑一方不会改变另一方。

同一个内部适配器进程承载两平台，不增加新的公网端口。客户端播放状态记录平台，自动下一首、暂停恢复和失败重试均使用正确平台。

## 音乐食堂：精神食粮

音乐实验室的第一个页签，进入时默认打开音乐食堂；使用自主 Vue 搜索/播放页面。默认选中“华语聚合”，聚合 GD 公开 API 的网易云、JOOX 两个来源；支持分别筛选，Audius 保留为独立音乐可选来源。没有歌手快捷入口，不自动搜索默认歌手。米兔等外站 iframe 已移除。

华语数据由 [GD音乐台(music.gdstudio.xyz)](https://music.gdstudio.xyz/) 的 [公开 API](https://music-api.gdstudio.xyz/api.php) 提供，来源署名放在页面顶部“关于音乐”中，底部不再显示来源说明。只能使用上游正常返回的播放地址，不保证所有会员歌曲、原唱或完整版本可播。歌曲名含 Live、翻唱、伴奏等标记时显示版本，其余显示“未标版本”，不擅自标注原唱。JOOX 当前部分歌曲能搜索但无播放地址，界面明确提示。

`GET /api/canteen/search?q=十年&source=all&page=1`：要求食堂登录；来源白名单 `all/netease/joox/audius`，关键词不超过 80 字。华语两个来源并行请求，单源失败仍返回另一来源结果及各源状态；保留来源+ID，分页去重不会混淆跨平台编号。

`POST /api/canteen/playback` 接受 `{source,id}`，按需获取 128kbps 音频地址；无地址返回明确错误。“换源找同曲”搜索另一来源，用户选择候选，不自动用翻唱替代原唱。音频直接由浏览器播放，不在食堂服务器代理、下载或长期存储。

GD 上游请求共享滑动限流：全站所有用户/所有操作合计每 5 分钟最多 40 次，低于文档 50 次限制。搜索/音频地址有效结果缓存 2 分钟，空结果 15 秒；歌词缓存 10 分钟、空歌词 1 分钟，最多 256 项；上游拒绝/失败不缓存。搜索每账号每分钟 15 次、播放解析 20 次。只发送应用自己的 User-Agent，不转发食堂凭据、不伪装原站 Origin/Referer。只接受已知音频 CDN 的 HTTPS 地址。

网页支持搜索、分页、播放/暂停、全宽可拖动进度条、音量、上下首及加载/错误提示。歌词区位于进度条及播放控制上方。歌词使用 `GET /api/canteen/lyrics?source=netease&id=...`，优先使用搜索结果的 lyric_id，沿用食堂登录、来源白名单和全站共享限流。歌词与音频独立加载，失败不阻断播放；支持 LRC 多时间戳、偏移、翻译、当前行高亮、容器内自动滚动及点击歌词跳转。用户手动滚动后暂停跟随，可点击恢复。Audius 暂无歌词接口，显示无歌词提示。切换菜单、订单、生存指南或音乐实验室页签时保持播放；顶部常驻控制条显示歌曲、状态及暂停/继续、上一首/下一首，点击歌名回到音乐食堂。音乐组件在同一账号内保留，退出/切换账号或卸载页面时才停止并清理；过期搜索和播放响应被忽略。小程序现使用原生音频与滑块，开发预览适配情况见文末。精简 Go 容器只读挂载 Ubuntu 的 `/etc/ssl/certs/ca-certificates.crt`，正常校验外部 HTTPS。

验证：GD 样本搜索及《十年》《江南》《平凡之路》音频地址 HEAD 成功；测试覆盖共享限流、缓存、部分来源失败、无播放地址、来源编号隔离及 URL 校验。执行 `scripts/build.py` 完成构建和检查。

### 音乐食堂收藏

只用于音乐食堂，与网易云/酷狗平台的歌单及收藏无关。每首搜索结果与当前播放歌曲可收藏/取消收藏，“我的收藏”中可直接播放。按食堂账号在 PostgreSQL 的 `canteen_music_favorites` 表保存，以账号+来源+歌曲 ID 唯一标识；只保存歌曲元数据，不保存临时音频地址或音频文件。每账号最多 1000 首，重复收藏幂等，切换/退出账号不保留旧账号列表。

### 播放队列与模式

仅音乐食堂提供“播放全部”：搜索页加入当前已加载的全部结果，收藏页加入当前账号全部收藏。队列使用快照，后续搜索、分页或取消收藏不改变正在播放的队列。

四种模式：顺序播放（播到末尾停止）、随机播放（每轮无重复，跨轮避免立刻重播最后一首）、单曲循环、列表循环。随机播放的上一首按当前随机顺序返回；单曲循环支持手动上下首。切换模式保留当前歌曲，不重启播放。同曲自动循环复用已加载音频和歌词，不重新请求接口。切换账号或卸载页面清空队列，普通栏目切换保留队列；模式暂不跨会话保存。无法播放的歌曲会提示，可手动切歌或换源，不无限自动重试。

首页用 `v-show` 隐藏音乐实验室而不是卸载，同账号下保持音乐食堂组件及其 audio。页签浏览不会停止声音；开始播放网易云/酷狗歌曲时停止音乐食堂，音乐食堂点播时停止平台播放器，避免叠音。退出、跨标签页账号变更及页面卸载显式停止当前音乐食堂音频。顶部控制通过组件暴露的方法操作原播放器，不额外创建音频实例。刷新整个网页不恢复队列或自动播放。

顶部播放条中间显示当前时间轴歌词，下方显示译文或下一句；换行时轻量上滑过渡，过长的当前行在容器内横向滚动，暂停时停止横向滚动。复用音乐食堂已加载的歌词，不增加接口请求。手机窄屏将歌词放在控制条下方独占一行；前奏、加载、无歌词/无时间轴均有提示。

- 最近 12 轮完整对话、最多 24000 字进入模型上下文，失败/中断的半截回复不进入上下文；历史记录独立保存。单条输入上限 4000 字，Agnes 开启 `chat_template_kwargs.enable_thinking`，Groq 使用 `reasoning_effort=medium`；输出预算 4096 Token，思考内容不展示、不记录。

## 自动出餐

每 30 秒推进一阶段：30 秒制作中、60 秒可取餐、90 秒自动完成。顾客无需点击确认，店长无需接单或出餐。顾客订单页显示真实状态、连续进度条和秒级倒计时，阶段到点后主动刷新；服务端状态未同步时明确显示同步提示，不在客户端假设订单已完成。

`orders.auto_started_at` 持久保存起点；后台单个共享任务每秒批量更新到期订单，不为每单创建计时器。关闭网页、服务重启不重置时间，重启立即补进度。旧活跃订单从现有阶段续跑，已取消/完成订单不变；幂等迁移不重置已配置的起点。

管理员状态接口仅保留未出锅订单的取消退款，拒绝手动推进；自动更新不会再次扣费或退款，也不会推进已取消的订单。原有菜单和顾客管理继续保留。`AUTOMATIC_ORDERS_TEST_DATABASE_URL` 用于一次性数据库边界测试；`scripts/automatic-orders-smoke.py` 用临时顾客账号验证线上 90 秒自动流程，不需要管理员登录。

### 精神疗愈角色资料

每次发送都由服务端注入完整身份卡与对应 MBTI 虚构角色档案：性格底色、关注点、说话习惯、陪伴方式、避免的刻板表现，覆盖 16 种角色。身份卡明确区分角色名字和用户名字，包含用户补充的背景/偏好。旧会话下一次回复同样应用更新，无需删除历史或重建角色。

日常对话以角色口吻自然接话，减少模板式共情、说教和无关的 AI 自我声明；询问 MBTI/角色时直接回应角色设定。明确询问是否真人或 AI 时保持诚实，不虚构现实身份或亲身经历。MBTI 资料是用于创作的风格设定，不用于诊断或推断真人心理。

### MBTI 连续聊天（2026-10-11）

16 种人格继续注入完整档案，但撤销固定字数、短句优先和强制陈述句收尾。允许角色世界里的虚构日常，明确询问真实身份时仍诚实说明 AI。当前消息放在写作提醒之后，追问会带上上一轮角色原话，帮助模型理解省略的主语和内容；数据库保存用户原文，不保存内部说明。

普通聊天保留逐段 SSE 输出；追问仅暂存仍可能与上一句相同的开头，一旦出现新内容即发出：追问若原样复读上一句（忽略标点空格），只重试一次，仍复读则报告失败，不伪造答案。复读比较会忽略少数固定接尾问句（如“你呢”），避免重复正文靠换个接尾就绕过检查；已流出的正常回复不会为清理问句而被收回。没有每 N 轮必须问或不问的规则。疑似复读的开头可能暂缓显示，正常新内容不等待整段生成；已显示文字不会回改，前端保留等待和停止生成操作。

### 多渠道与响应等待（2026-10-12）

按上述渠道顺序调用：首个正文或思考进展等待12秒，每家调用最多20秒，整轮模型阶段最多40秒（包含最多一次复读重试）。这些是等待预算，不是速度承诺。失败后按 Retry-After 冷却，未提供时默认60秒；冷却结束重新尝试首选。正文中途失败保留部分内容并提示重试，不拼接另一模型。免费额度全不可用时提示稍后重试，不启用其他模型或自动开通付费。

全部16种 MBTI 使用同一套人格档案生成器，包含身份、四维偏好、基本与深入人物档案、说话方式、情绪与关系边界和当前上下文；系统提示说明「精神离职 / 精神疗愈」的休闲角色聊天用途。没有固定回复字数或每句必须反问的要求。

`scripts/healing-style-eval.py --provider Agnes` 或 `--provider Groq` 选择合成对话评估，可加 `--dialog`、`--topic`、`--timing`、`--role ENFP`。密钥仅在服务器读取，测试默认不调用真实接口。各渠道使用各自账号免费权限；部署不会变更服务商账单设置，免费政策仍以账号与服务商为准。
